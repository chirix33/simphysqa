# Blocker report to relay to the planning assistant

Use this structure for a real unresolved issue. Complete useful independent work first; do not treat a missing GPU as a block on typed contracts or dataset tests.

- Phase/substep and status:
- Repository branch/commit and relevant file paths:
- Expected behavior and source requirement:
- Exact command/minimal reproducer:
- Observed behavior and sanitized traceback/log excerpt:
- Environment (OS, Python, relevant package versions, CPU/GPU/runtime):
- Attempts already made and their outcomes:
- Root cause confirmed or hypotheses still untested:
- Impact: what is blocked, what is complete, what can continue:
- Option A and tradeoff:
- Option B and tradeoff (if genuinely viable):
- Recommended option and why it preserves project decisions:
- Smallest question needing the user/planner answer:
- Evidence needed to close this blocker:

Do not include keys, tokens or unrelated environment variables. A library failure is not permission to change the scientific objective; a scientific ambiguity is not resolved by whichever function is easiest to implement.
